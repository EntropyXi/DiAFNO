# 冒烟 0.42 与当前 0.69–0.70 平台：损失标度换算与验证停滞分析

状态：分析报告（分支 B 从零残差训练，epoch 4→18 验证停滞问题）
依据：上一会话完整记忆（session-902d8bac / 2e40e436 转录）+ 本会话对
`diafno/models/diffusion.py` 损失公式的复核 + 300 万样本蒙特卡洛计算。

## 1. 两个 run 的实际配置（先对齐事实）

| 项目 | 冒烟（用户记忆里的 "0.4"） | 当前训练（分支 B scratch） |
|---|---|---|
| 目标 | residual | residual |
| σ_data | 0.15 | 0.15 |
| **P_mean** | **−1.2（默认值）** | **−3.0（显式传入）** |
| 起点 | 从零，batch=1，1000 步 | 从零，batch=16×2 卡，35 epoch |
| 训练损失 | **0.4245**（epoch 均值；中位 0.323，min 0.051，max 2.05） | **0.69–0.70 平台**（epoch 1≈0.92 → epoch 4≈0.70 → 之后平坦） |

**唯一对损失数值有决定性影响的差别是 P_mean**（−1.2 → −3.0，σ 中位数从 0.30 移到 0.05）。
两个 run 的损失**不在同一把尺子上**，不能直接比大小。

## 2. 冒烟 0.42 是怎么来的（答案：旧 σ 分布的低地板）

EDM 损失在最优去噪器下的逐 σ 下限：

```
L(σ) = v·(σ² + σ_data²) / (σ_data²·(v + σ²))     （v = 条件残差方差，z² 单位）
       σ→0 时 L→1（与 v、σ_data 无关）；σ→∞ 时 L→v/σ_data²
```

把 σ 采样质量从 σ≈0.3（P_mean=−1.2）整体下移到 σ≈0.05（P_mean=−3.0），
等于把损失表面整体推向 L→1 的高值区。用逐 lead 残差方差
（std 0.215→0.730 K，sst_std=9.571 K，v=0.0005→0.0058）做 300 万样本 MC：

| 配置 | 逐 lead 下限 | lead 平均下限 | 实测损失 | 相对下限 |
|---|---|---|---|---|
| 冒烟 (0.15, −1.2) | 0.063–0.390 | **0.215** | 0.4245 | ≈2.0×（1000 步欠拟合） |
| 当前 (0.15, −3.0) | 0.311–0.713 | **0.537** | 0.695 | ≈1.3×（边际方差口径） |

**双向换算**（把实测损失反解成隐含条件方差 v_c，再换到对方分布下重算）：

- 冒烟 0.4245 ↔ v_c≈0.0066 z²（条件 RMSE≈0.78 K）→ 换到当前分布会打印 **≈0.737**；
- 当前 0.695 ↔ v_c≈0.0053 z²（条件 RMSE≈0.70 K）→ 换到冒烟分布会打印 **≈0.365**。

结论：**冒烟的 0.4 不是"更好的模型"，而是"更低的损失地板"造成的。**
把冒烟模型放到现在的 σ 分布下它会显示 0.74；把当前模型放到冒烟分布下它会显示 0.37
（比冒烟还低）。当前 0.69–0.70 的去噪质量 ≥ 冒烟模型，且离自己的理论下限更近。
计划 v2 §0 已预告过这一点（"新分布下限 0.45–0.55，不是 0.13–0.15"）。

## 3. 为什么卡在 0.69–0.70（还有多少可降空间）

1. **可降空间不大**：边际方差口径的下限是 0.537；真实（条件）下限更低（≈0.4–0.5）。
   平台 0.695 距下限约 0.15–0.25，不是"3× 停滞"。
2. **平台机制 = 重尾梯度噪声 + 梯度裁剪**：P_mean=−3.0 下 E[λ]≈7131，
   **84.9% 的损失权重集中在 σ<0.01**（约 2.8% 的样本，λ≈1e4–1e7）；
   σ≥0.03 的区间只占权重 2.8%。损失均值被极少数巨权样本支配，
   批间方差巨大；max_grad_norm=1.0 的裁剪又把巨权样本的梯度截断 → 卡在
   "梯度噪声地板"上，高于理论下限。计划 R4 的预案就是冲这个（clip>30% → 2.0）。
3. **学习率拖累逃脱**：cosine（2e-4→1e-6，T_max=34125），epoch 18 时 lr≈9.5e-5、
   继续向 1e-6 衰减，噪声地板之上的残差无法被爬出。
4. 0.695 对应的隐含条件 RMSE≈0.70 K（训练标度）——模型已学到很接近数据
   残差尺度的条件均值，剩下的可学损失本来就少。

## 4. 为什么验证 Overall RMSE 从 epoch 4 到 18 没改善（三个叠加原因）

1. **主因：训练损失自己先停了**。epoch 4 之后 0.70→0.69，去噪器几乎不再变好，
   采样器输出自然不再变好。验证停滞首先只是训练停滞的投影。
2. **采样路径被"中等 σ 区间"把持，而该区间几乎不受训练损失约束**：
   16 步采样从 σ=1.0 起，前 ~10 次去噪评估落在 σ≥0.029 的区间，
   该区间只占训练损失权重的 **~2.8%**（σ≥0.017 也只有 7.2%）。
   轨迹末端的噪声水平由这个"没人管"的中等 σ 区间决定；
   损失可见的小 σ 改进（条件均值）几乎不改变轨迹终点 → 验证值不动。
3. **训练/验证增量尺度错配（方向性证据，待全量确认）**：
   训练段逐 lead 残差 std 0.215→0.730 K（lead 平均 RMSE≈0.51 K），
   而验证段 persistence 是 day1 0.25 K / day15 1.58 K / overall 1.19 K——
   验证段增量比训练段大约 2.3×。模型在 ±0.5 K 增量上标定，
   验证时面对 ±1.2 K 增量，加上 (2)，验证 RMSE 就停在
   "persistence+采样噪声" 的 ≈1.4–1.5 K（冒烟同管线就是 1.498 K）。
   注意：训练侧增量统计来自 256 行抽样（上一会话已标记季节混叠风险），
   需在服务器全量 train/val 上复核后才能定谳。

## 5. 判定与判别实验（全部用现有代码，零改动）

- **0.69–0.70 是"健康但略高于可达下限"的平台**，不是绝对模式那种
  "已到下限"的收敛，也不是冒烟式的欠拟合；损失按计划 v2 只是健康参考，
  硬门槛仍是验证 RMSE（day1≤0.5 K、overall≤1.4 K）。
- 判别实验（服务器 GPU 2/3，每项 ~10 分钟）：
  1. **fixed-σ probe**：`validate_ostia.py --checkpoint .../best_model.pth --probe-sigma 0.002`
     ——绕开采样器直接测条件均值。若 probe overall ≈0.7–0.8 K 而采样 ≈1.4–1.5 K
     → §4(2) 采样门定谳；若 probe 也 ≈1.4 K → 条件均值本身弱，转向 §4(3) 或容量。
  2. **--sampling-steps 32** 对同一 checkpoint 验证 → 轨迹离散化对照。
  3. 读 `epoch_metrics.jsonl` 与梯度范数曲线：clip 率>30% → max_grad_norm 2.0（计划 R4）。
  4. 若采样门定谳：中等 σ 补救二选一——P_mean=−2.3 折中（下限 0.41、信息带 69%，
     上一会话已算）或短程二次微调专攻 σ∈[0.03,1.0]。
  5. 服务器 5 分钟 h5py 脚本：全量 train/val 逐 lead 残差 std，确认/推翻 §4(3)。
